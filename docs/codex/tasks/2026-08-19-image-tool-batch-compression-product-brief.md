# 图片工具批量与压缩产品简报

- 调研日期：2026-08-19
- 产品定位：TTool 内嵌、本地优先的轻量批量图片压缩器；不是重型图片编辑器。
- 当前缺口：已有单图尺寸、旋转、翻转与 PNG/JPEG/WebP 导出，但缺少多文件队列、显式批量执行、实际压缩反馈与可靠的一次性下载。

## 竞品观察

| 产品 | 官方事实 | 对 TTool 的启示 |
| --- | --- | --- |
| TinyPNG | 免费入口支持一次最多 20 张、每张 5 MB；提供自动有损压缩与 AVIF/JXL/WebP/JPEG/PNG 转换；上传文件最多保留 48 小时。来源：https://tinypng.com/ | 批量入口和“无需理解编码器”的默认值很重要；TTool 可用本地处理形成隐私差异化。 |
| Squoosh | 强调打开一张图片、检查差异、调节设置并保存；全部图片处理在本地完成。来源：https://squoosh.app/ ，https://github.com/GoogleChromeLabs/squoosh | 保留可解释的质量调节、预览与本地处理，但不要照搬单图工作流。 |
| iLoveIMG | 压缩页支持多选/拖放并同时压缩；缩放页支持批量按像素或百分比、保持比例和不放大小图；处理后可下载或回存云端，服务器文件在两小时内删除。来源：https://www.iloveimg.com/compress-image ，https://www.iloveimg.com/resize-image ，https://www.iloveimg.com/help/documentation ，https://www.iloveimg.com/help/security | 批量统一设置、逐项结果尺寸与清晰的处理进度是核心；TTool 本轮不引入云端。 |
| Caesium Web | 支持 JPG/PNG/WebP、有损/无损、元数据保留、前后对比；图片完全在浏览器本地处理，当前在线入口标注最多 10 张、每张 20 MB。来源：https://caesium.app/ ，https://github.com/lymphatus/caesium-app-web/ | 本地批量压缩、实际前后反馈与诚实的格式能力边界适合 TTool。 |
| XnConvert | 桌面端以文件/文件夹 → 动作 → 输出组织批处理，支持压缩质量、状态错误/警告、命名、预设、监听文件夹和 80+ 动作。来源：https://www.xnview.com/en/xnconvert/ ，https://www.xnview.com/en/how-to-batch-convert-and-batch-process/ | 三阶段批处理结构成熟，但大量编辑动作会使 TTool 失焦；命名、预设与文件夹工作流应延后。 |

## 本轮 MVP（已冻结）

1. 本地多文件队列：文件选择与拖放均支持多选；最多 20 张、总源文件不超过 200 MiB；无上传，原文件不修改。
2. 队列管理：显示文件名、格式、尺寸、源体积与状态；可切换预览、移除单项、清空；无效或损坏文件提供逐项错误，不阻断其他图片。
3. 统一变换：保留原尺寸、按百分比、限制最长边、固定宽高；继续支持旋转、水平/垂直翻转和选中项预览。
4. 显式压缩：JPEG/WebP 提供 1–100 质量，PNG 明确标为无损重编码且可能不会变小；格式转换必须由用户明确选择。
5. 批量执行：逐张解码和编码，限制峰值内存；展示总进度，并为每项记录成功/失败、输出格式/尺寸、实际输出体积和节省比例。
6. 下载：成功项可单独下载；“下载全部”生成无依赖、文件名冲突安全的 ZIP。图片已经编码，因此 ZIP 使用 store 模式，不再重复压缩。
7. 生命周期：替换、移除、重跑、清空和卸载时释放 ImageBitmap、Blob URL 与定时器；批量结果与 ZIP 均不写入源文件。

## 后续优先级

### P1

- 目标文件体积：对 JPEG/WebP 迭代编码并提示无法达到的下限。
- 命名模板与冲突策略：前后缀、序号、保留目录结构。
- 元数据策略：明确“移除 / 尽力保留”，需要兼容性与隐私测试。
- 单项覆盖：在统一设置之上为少数图片单独调整。

### P2

- 常用预设与最近设置。
- 文件夹导入/监听；需要 Electron 平台适配与权限、生命周期设计。
- AVIF/JXL、真正的 PNG 优化与更多无损编解码器；需要评估 WASM/生产依赖和包体。
- 面向社交平台的尺寸预设。

### 明确不做

- 本轮不增加自由裁剪、修图、滤镜、图层、AI 抠图、水印编辑器。它们不是批量压缩闭环的必要条件，会显著增加交互与验证面。

## 验收重点

- 混合 PNG/JPEG/WebP 与一个无效文件同时导入；正确显示数量、尺寸、体积与逐项状态。
- 统一尺寸/旋转/翻转对所有有效项生效；逐张顺序执行，单项失败不阻断后续。
- 实测输出 MIME、像素尺寸、体积和节省比例；PNG 体积增加时不得伪称“已压缩”。
- ZIP 条目数等于成功项数，重名输出在 ZIP 内唯一且可解压；单项下载仍可用。
- 原文件字节不变；队列重跑、删除、清空和卸载后无遗留 Object URL 或测试资源。
