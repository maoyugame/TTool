# TTool 截图贴图截图完成浮窗与标注能力增强

## 背景

本规格承接截图贴图 v1 的新一轮用户反馈，目标是把普通 `截图` 从“选区确认后立即打开 TTool 工具页”调整为“选区确认后先显示右下角截图浮窗，用户点击浮窗才进入标注编辑器”。同时补齐标注编辑器默认适配、圆形标注、点选选择标注，以及矩形/圆形携带文本能力。

本阶段只产出 Engineering-ready 交互规格，不修改业务代码，不生成视觉资产，不改变插件 SDK screenshot 非暴露边界。

## 设计结论

- 普通 `截图`：选区确认后不再立即打开或聚焦 TTool 主窗口；截图进入最近 5 张队列，并在选区所在显示器右下角显示一个截图完成浮窗。
- 点击浮窗：打开/聚焦 TTool，进入 `截图贴图` 工具，并把该截图加载到 `AnnotationEditor`。
- 浮窗自动消失：无操作 5 秒后关闭；鼠标悬停或键盘焦点在浮窗内时暂停计时，离开/失焦后重新计 5 秒。
- `截图并贴图`：保持现有自动创建贴图行为，不经过截图完成浮窗。
- 标注编辑器：每次打开截图默认进入 `适配` 视图模式；用户手动缩放或平移后进入手动视图。
- 标注工具：新增 `圆形`；`选择` 模式支持直接点选单个标注、拖动移动、Del/Backspace 删除。
- `矩形` 与 `圆形` 工具新增 `携带文本` 勾选框；勾选后每次成功绘制形状都会自动创建关联文本输入并聚焦。

## 截图完成浮窗

### 触发矩阵

| 入口 | overlay 操作 | v1 行为 |
| --- | --- | --- |
| `截图` | `✓` 或双击选区 | 保存到最近截图，显示截图完成浮窗，不打开 TTool |
| `截图` | `复制` | 保持现有复制到剪贴板，不显示浮窗 |
| `截图` | `保存` | 保持现有保存流程，不显示浮窗 |
| `截图` | `贴图` | 保持现有创建贴图，不显示浮窗 |
| `截图并贴图` | `✓` 或双击选区 | 保持现有自动创建贴图，不显示浮窗 |
| 任一入口 | `取消` / Esc / 无效选区 | 不显示浮窗 |

### 流程

1. 用户点击工具页顶部 `截图` 或触发截图快捷键。
2. 用户在 overlay 中选择区域并点击 `✓`，或在有效选区内双击。
3. Electron 主进程裁剪截图，写入最近截图队列。
4. 主进程创建截图完成浮窗；TTool 主窗口不 `show`、不 `focus`、不自动切换到截图贴图工具。
5. 用户点击浮窗主体或缩略图，浮窗关闭，主窗口打开/聚焦，`截图贴图` 工具页加载该截图到 `AnnotationEditor`。
6. 若用户 5 秒内无操作，浮窗关闭；截图仍保留在最近 5 张队列中。

### 浮窗布局与状态

浮窗建议使用独立 Electron `BrowserWindow`，不作为主窗口内 DOM 或 pin window。布局复用现有 token，不需要新增图标或图片资产。

- 尺寸：建议宽 280px，高 96-112px；最小宽 240px，最大宽 320px。
- 内容：
  - 左侧缩略图，建议 86x58 或 96x64，`object-fit: cover`。
  - 主文案：`截图已完成`。
  - 次文案：尺寸，例如 `456 × 314px`，以及 `点击标注`。
  - 右上角可提供文本关闭按钮 `×` 或 `关闭`，点击只关闭浮窗，不打开工具。
- 点击区域：
  - 点击浮窗主体、缩略图或主文案均打开标注编辑器。
  - 点击关闭按钮只关闭浮窗。
- 键盘：
  - 浮窗获得焦点时，Enter/Space 打开标注编辑器。
  - Esc 关闭浮窗。
- 计时：
  - ready-to-show 后开始 5 秒计时。
  - `mouseenter` / `focusin` 暂停计时。
  - `mouseleave` / `focusout` 后重新计 5 秒。
- 可访问性：
  - 窗口 title：`截图已完成`。
  - 主按钮 aria-label：`打开截图标注编辑器`。
  - 关闭按钮 aria-label：`关闭截图完成浮窗`。

### 位置与层级

- 位置：使用本次选区所属显示器的 `workArea` 右下角。
- 边距：右侧 16px，底部 16px；若系统任务栏占用底部或侧边，必须使用 `workArea` 避让。
- 多显示器：在哪个显示器完成选区，就在哪个显示器右下角显示；displayId 缺失或显示器已变化时，回退到当前鼠标所在显示器，再回退到主显示器。
- 缩放：坐标使用 Electron display DIP 坐标，不手动按截图像素尺寸换算。
- 层级：浮窗 always-on-top、skipTaskbar、无边框、不可调整大小；显示时不抢主窗口焦点，优先 `showInactive()`。用户点击后才聚焦主窗口。
- 与 overlay：overlay 关闭并完成截图裁剪后才显示浮窗，浮窗不与截图 overlay 同时出现。
- 与贴图窗口：浮窗不是贴图，不进入当前贴图列表，不参与 `关闭全部`。

### 重复截图

v1 采用“单个最新截图完成浮窗”：

- 若已有浮窗未关闭，又完成了一次新的普通 `截图`，关闭旧浮窗并显示新浮窗，计时重新开始。
- 旧截图不丢失，仍位于最近截图队列中，可从工具页左侧最近截图打开。
- 不做多浮窗堆叠，避免右下角遮挡和窗口生命周期复杂度。

### 失败与取消

- 截图取消、Esc、选区过小、截图裁剪失败：不显示浮窗。
- copy/save/pin 失败：保持现有状态提示路径，不显示浮窗。
- 浮窗打开标注时，如果主窗口加载失败或截图数据失效，关闭浮窗并通过主窗口状态区显示错误；截图仍尽量保留在最近截图队列。

## AnnotationEditor 默认适配

### 初始状态

- 每次 `AnnotationEditor` 接收新的 `capture` 时，视图模式初始化为 `fit`。
- 图片加载完成且 viewport 尺寸可测量后自动执行一次 `fitZoom`。
- `fit` 视图应让整张截图完整可见，并在可滚动区域中居中。
- fit 缩放仍受现有 `MIN_ZOOM` / `MAX_ZOOM` 限制；小图允许被适度放大，但不超过最大缩放。

### 手动视图

- 用户点击 `＋`、`−`、`100%`、Ctrl/Meta + wheel 后，视图模式切换为 `manual`。
- 用户使用 `拖拽` 工具、Space 平移或中键平移，不改变缩放模式；如果当前是 `fit`，只记录滚动位置变化，不在 resize 时强行回中，除非用户再次点击 `适配`。
- 用户点击 `适配` 后，视图模式重新变为 `fit`，并立即重新计算缩放和居中。
- viewport 尺寸变化时：
  - `fit` 模式下重新计算适配缩放；
  - `manual` 模式下保留当前 zoom 和 scroll。

## 圆形标注

### 工具入口

- 在工具分段控件中新增 `圆形`，建议放在 `矩形` 后、`画笔` 前。
- `圆形` 工具显示与 `矩形` 相同的属性控件：颜色、线宽、`携带文本`。
- 不新增 icon 或视觉资产。

### 绘制行为

- 拖拽创建圆形标注，使用拖拽起点和终点形成的归一化边界框。
- 渲染使用 `ctx.ellipse` 或等价实现；UI label 仍为 `圆形`，工程数据可使用 `kind: 'circle'` 且包含 `x/y/width/height/color/lineWidth`。
- 默认允许宽高不等的椭圆外观；按住 Shift 绘制时锁定为正圆。若 Engineering 为 v1 降低复杂度，可先不支持 Shift 锁定，但不能影响普通圆形/椭圆绘制。
- 边界框宽或高小于 4px 时不提交标注。
- 拖拽方向不影响结果，向左上/右下等方向都应归一化为正宽高。

### 选择、移动与导出

- hit-test 使用圆形/椭圆外接边界框与实际椭圆共同判断；点在填充区域内或描边附近都可以选中，容差与矩形一致。
- 选择态绘制沿用现有青色选择框，选择框使用圆形外接矩形，不需要圆形专用控制点。
- 移动时整体平移 `x/y`，保持宽高、颜色、线宽不变，并沿用图片边界夹紧规则。
- 导出时只渲染圆形描边，不包含选择框、label 或任何编辑器 UI。

## 点选选择标注

### 与现有 `选择` 工具关系

- 点选选择属于 `选择` 工具能力，不在 `箭头`、`矩形`、`圆形`、`画笔`、`文本`、`马赛克` 等绘制工具中隐式触发。
- 绘制工具处于激活状态时，点击或拖拽优先执行绘制；如果已有选中对象，开始绘制时清空选择。
- `选择` 工具保留框选能力：点击空白并拖拽为框选；点击标注为点选。

### 点选规则

- 单击标注：选中该标注，清空其他选择。
- Shift + 单击标注：追加到当前选择。
- Ctrl/Meta + 单击标注：切换该标注的选中状态。
- 点击空白：
  - 无修饰键：清空选择，并可开始框选。
  - Shift 或 Ctrl/Meta：不立即清空，拖拽时按追加/切换语义框选。
- 多个标注重叠时，选择视觉上最上层的标注，即 annotations 数组中最后绘制/最后添加的命中项。

### 移动与删除

- 选中标注后，按住该标注拖动可移动选中集合。
- 移动阈值建议 1-3px；低于阈值视为普通点选，不写入 undo。
- 成功移动一次写入一个 undo 快照；redo 可恢复移动。
- Del 或 Backspace 删除当前选中标注；当焦点在文本输入框或可编辑元素内时，Del/Backspace 优先由输入框处理，不删除标注。
- Esc 优先级：取消文本草稿 > 取消正在移动/框选 > 清空当前选择。

## 矩形/圆形携带文本

### UI

- 当工具为 `矩形` 或 `圆形` 时，在颜色、线宽控件后显示勾选框：`携带文本`。
- 默认状态：关闭。
- 状态作用域：当前编辑器会话内保持；切换工具不重置；打开新的 capture 时重置为关闭。
- 勾选后建议显示复用的 `字号` 控件，文本颜色使用当前形状颜色。

### 创建行为

1. 用户选择 `矩形` 或 `圆形`。
2. 勾选 `携带文本`。
3. 用户拖拽创建有效形状。
4. pointer up 后提交形状，并立即创建一个文本草稿输入框。
5. 输入框自动聚焦并选中空内容，用户可直接输入。

### 文本初始位置

- 文本标注仍使用现有 top-left 锚点。
- 默认位置为形状边界框左上角内缩 10px：`x + 10`、`y + 10`。
- 若形状过小导致该位置越界，则夹紧在图片范围内；不为了 v1 引入文本对齐、自动换行或自动跟随形状缩放。
- 文本提交后是独立文本标注，但在 undo 分组上与刚创建的形状视为一次创建操作。

### 输入结束规则

- Enter：提交非空文本；空文本则只保留形状并丢弃文本草稿。
- Blur：与 Enter 相同，提交非空文本；空文本丢弃草稿。
- Esc：取消文本草稿，只保留形状。
- 用户切换工具、点击其他 toolbar 操作、复制/保存/贴图前，先按 blur 规则结算文本草稿。

### Undo / Redo 分组

- 携带文本创建应作为一个 undo 分组：
  - 非空文本提交后，一次 undo 同时移除形状和文本。
  - 空文本或 Esc 后，一次 undo 移除形状。
- Redo 应恢复同一组结果。
- Engineering 建议增加 `commitAnnotationGroup([shape, text?])` 或等价事务，避免先提交形状再提交文本形成两个 undo 步骤。

### Export

- 导出时包含已提交的形状和文本。
- 如果导出前仍有文本草稿，先按 blur 规则结算；非空文本进入导出，空文本不进入导出。
- 导出图片不得包含输入框、选择框、toast 或其他编辑器 UI。

## Deferred

- 不做多浮窗堆叠。
- 不做对象 resize / rotate。
- 不做图层面板。
- 不做文本自动换行、文本与形状绑定移动以外的高级联动。
- 不生成视觉资产、mockup、icon 或截图示意图。
